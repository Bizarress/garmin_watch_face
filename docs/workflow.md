# 候補ごとの進め方

1 つの候補を「仕様 → デザイン → 実装 → シミュレーター確認」の順に進めます。
作業はすべて `faces/<番号-名前>/` の中で完結させます。

## 1. 仕様を固める（`README.md`）

- 「未決事項」を 1 つずつ決めて、本文に反映する
- 表示するデータごとに、取得元の API と「取れないときの表示」（`--` など）を決める
- 常時表示（AOD）の画面を決める。明るい地の案は暗い版が必須
- 設定項目（色の切り替えなど）を出すかどうかを決める

## 2. デザイン案を作る（`mock/`）

- `mock/index.html` は選定時のモック。仕様を詰める中で描き直したら、同じフォルダに追加する
- 実機の `Dc` で描ける表現に限る（グラデーションは細い帯の重ね描き、ぼかしは不可など。`docs/device-notes.md`）
- 案の「らしさ」を作っている要素（細かい文字の密度、装飾）は残す。読みやすさのために一律で文字を大きくしない

## 3. 実装する（`app/`）

- `app/` は `template/` から作ったもの。描画は `source/GarminWatchFaceView.mc` に書く
- 自前のフォントや画像は `resources/` に置く
- メモリ上限は 128KB（ウォッチフェイス）。大きな画像は避け、図形で描けるものは図形で描く

## 4. ビルドとシミュレーター確認

```powershell
.\scripts\build.ps1 <番号-名前>
.\scripts\sim.ps1   <番号-名前>
```

確認すること：

- [ ] 警告なしでビルドできる
- [ ] 通常表示がモックどおりに見える（シミュレーターの画面を保存して見比べる）
- [ ] 時刻の桁が変わっても崩れない（`0:00`、`9:59`、`12:00`、`23:59`、12 時間表記）
- [ ] データが取れないとき（心拍なし、天気なし）に崩れない
- [ ] 常時表示に切り替わり、焼き付き対策（位置ずらし・点灯画素の少なさ）がされている
- [ ] 小さな文字がシミュレーター上で読める
- [ ] メモリ使用量に余裕がある（シミュレーターの「View Memory」）

## 5. 状態を更新する

- `faces/<番号-名前>/README.md` 冒頭の「状態」を更新する
- `faces/README.md` の一覧の「状態」を更新する
